I.PENDAHULUAN

Dokumen ini adalah pasangan dari Spesifikasi Teknis Web Service SSW – MPPD. Jika dokumen tersebut menjelaskan cara P-MPPD mengirim data permohonan ke SSW (POST /integrasi/ssw-mppd), dokumen ini menjelaskan arah sebaliknya: cara SSW mengirim hasil verifikasi teknis (disetujui / ditolak) kembali ke P-MPPD setelah dinas teknis memutuskan.

P-MPPD (Pelayanan MPP Digital) adalah aplikasi milik Dinas Penanaman Modal dan Pelayanan Terpadu Satu Pintu Kota Surabaya untuk mengelola permohonan Surat Izin Praktik (SIP) tenaga kesehatan. Seluruh endpoint bersifat RESTful, memakai format JSON, dan stateless (tanpa sesi, tanpa CSRF).

Base URLhttps://pmppd.dpmptsp-surabaya.my.id/api
FormatJSON, UTF-8 — header Content-Type: application/json dan Accept: application/json
Zona waktuAsia/Jakarta (WIB, UTC+7)

II.OTENTIKASI

Metode otentikasi memakai Laravel Sanctum, sama dengan yang dipakai SSW. SSW login dengan akun sistem P-MPPD yang disediakan DPMPTSP, menerima token, lalu memakainya sebagai Bearer Token pada endpoint callback. Token tidak memiliki masa berlaku — cukup login sekali, simpan, dan pakai ulang. Bila menerima respons 401, login ulang sekali lalu ulangi request.

III.ALUR INTEGRASI

NoArahLangkah
1P-MPPD → SSWPOST /integrasi/ssw-mppd (id_layanan 36). Payload memuat nomor_register.
2SSW → P-MPPDRespons insert memuat id_t_permohonan_det; P-MPPD menyimpannya pada berkas.
3—Berkas menunggu keputusan dinas teknis di sisi SSW.
4SSW → P-MPPDPOST /api/login dengan akun sistem → Bearer token (sekali, disimpan).
5SSW → P-MPPDPOST /api/ssw/callback + Bearer → keputusan disetujui / ditolak.

Kunci yang dikenal kedua sisi:

KunciAsalDipakai untuk
nomor_registerDikirim P-MPPD di payload MPPDWajib di callback — mengenali berkas
id_t_permohonan_detDikembalikan SSW saat insert MPPDOpsional di callback — pengaman agar callback tidak nyasar ke berkas lain

4.5.Kode Error

Selain 401 dan 429, seluruh body error berbentuk { "success": false, "message": "…" }.

HTTPKapanPesan
401Token tidak ada / tidak valid / sudah dicabut{ "message": "Unauthenticated." }
403IP atau akun tidak masuk daftar yang diizinkanAlamat IP tidak diizinkan. / Akun ini tidak diizinkan mengirim callback.
404nomor_register tidak ditemukanPermohonan dengan nomor register X tidak ditemukan.
409id_t_permohonan_det tidak cocok dengan yang tersimpanid_t_permohonan_det tidak cocok untuk X (dikirim: …, tersimpan: …).
422Payload tidak validPayload tidak valid. + rincian per field di errors
429Melebihi rate limitToo Many Attempts.
503Endpoint callback sedang dinonaktifkan oleh P-MPPDEndpoint callback SSW sedang dinonaktifkan.

Anjuran retry di sisi SSW: ulangi hanya untuk 429, 503, 5xx, dan kegagalan koneksi (dengan backoff eksponensial). Jangan ulangi 4xx lainnya — perbaiki payload terlebih dahulu.

V.IDEMPOTENSI

Callback yang sama boleh dikirim lebih dari sekali. P-MPPD mengenali pengulangan dengan urutan berikut:

  1. Jika event_id dikirim dan sama dengan event_id yang terakhir diproses untuk berkas itu → duplikat.
  2. Jika tidak ada event_id: bila status berkas sudah sama dengan hasil keputusan dan sudah pernah diverifikasi → duplikat.

Duplikat dijawab 200 dengan duplikat: true dan tidak mengubah apa pun. Keputusan baru yang berbeda (misalnya ditolak setelah disetujui) akan diproses dan menimpa status sebelumnya — kirim hanya keputusan final.

VII.CONTOH PEMANGGILAN (cURL)

BASE=https://pmppd.dpmptsp-surabaya.my.id/api
# 1) Login — simpan token
TOKEN=$(curl -s -X POST "$BASE/login" \
  -H "Content-Type: application/json" -H "Accept: application/json" \
  -d '{"email":"ssw-integrasi@dpmptsp.surabaya.go.id","password":"********","device_name":"ssw-produksi"}' \
  | jq -r .token)
# 2) Kirim keputusan
curl -s -X POST "$BASE/ssw/callback" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -H "Accept: application/json" \
  -d '{
    "nomor_register": "REG-2026-0012345",
    "id_t_permohonan_det": 1234,
    "status": "disetujui",
    "verifikator": "Dinas Kesehatan Kota Surabaya",
    "tanggal_verifikasi": "2026-09-14 10:32:00",
    "keterangan": "Berkas lengkap dan sesuai.",
    "event_id": "ssw-evt-7f3a9c",
    "nomor_sip": "SIP-503.445/2026/DINKES",
    "tanggal_terbit_sip": "2026-09-14",

  }'

VIII.HAL YANG PERLU DISEPAKATI

Dari tim SSW ke P-MPPD

  • Daftar IP publik server SSW yang akan memanggil callback (untuk whitelist).
  • Konfirmasi kosakata status yang dipakai SSW bila berbeda dari daftar di 4.4 — dapat ditambah tanpa perubahan kode.
  • Kepastian SSW mengirim event_id dan id_t_permohonan_det (sangat disarankan keduanya).

Dari P-MPPD ke tim SSW

  • Akun sistem (email + password) khusus integrasi — disampaikan lewat jalur aman, bukan lewat dokumen ini.
  • URL staging untuk uji coba sebelum produksi.

Kontak: Dinas Penanaman Modal dan Pelayanan Terpadu Satu Pintu Kota Surabaya — tim pengembang P-MPPD.
